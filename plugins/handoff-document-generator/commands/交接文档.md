# 生成交接文档

按 generate-handoff-document 技能的“手动模式”完整执行：

1. 只检查安全的项目资料，在工作区根目录原子生成符合 14 节固定结构的 HANDOFF.md。
2. 用插件的文件句柄扫描器检查精确文件字节，并保留其 SHA-256。
3. 创建任何任务前，通过有界 stdin JSON 把工作区根、HANDOFF 路径和扫描器 SHA-256 交给插件的 `backup` 命令。必须取得已验证的备份回执，不允许提示输入指定备份根；备份、配额或最终校验失败时立即停止。
4. 列出 Codex 项目并执行技能规定的 `project-target` 校验。只有一个已注册本地项目的规范路径与当前工作区完全相等时才能继续；禁止回退到无项目、远程、同名、父目录或子目录项目。没有唯一匹配时，在创建任务前按返回错误停止。
5. 在这个已验证本地项目中创建干净的新任务，禁止 fork。首条提示要求先验证项目备份再读取 HANDOFF.md，只放 HANDOFF 的绝对路径和 SHA-256、非敏感 handoff_id、经过验证的单行备份回执 ID，以及技能规定的固定安全提示。不得把原始备份路径注入新任务提示。
6. 新标题使用延续当前任务含义的简洁中文基名并添加连续的 （续接 N）；源标题已经是中文时清洗后原样延续，并先检查同名续接任务，避免序号重复。
7. 读回新任务，再用 Codex 导航工具打开同一个任务；只有打开成功后才能报告备份、创建、改名或导航成功。

手动入口不得依赖 Hook marker、request、claim、lease、transcript 或背景信息窗口。不得把 HANDOFF 全文、秘密、源 session 数据或运行时状态复制到新任务提示。

备份或任务管理工具不可用时，只报告已经验证的 HANDOFF.md 绝对路径、已有的备份路径和未完成阶段，不得伪报备份、创建、改名、附件或导航成功。
